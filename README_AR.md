# يلا بينا | YALBENA

**الإصدار المستهدف: 0.10.1 — التوزيع التلقائي بعد انتهاء مهلة عرض الكابتن**

منصة خدمات وتوصيل تبدأ من مدينة سوهاج بهوية راقية كحلي وذهبي.

## مكونات الحزمة الحالية
- `web-preview/`: صفحات المعاينة، بما فيها الصفحة الرئيسية ولوحة الإدارة ودليل السفر وصفحة نقل موظفي الشركات.
- `backend/`: واجهة API باستخدام NestJS.
- `database/`: المخطط الأساسي وترحيلات PostgreSQL حتى الترحيل 022.
- `apps/customer_app/`: تطبيق العميل.
- `apps/captain_app/`: تطبيق الكابتن.
- `docs/`: مستندات المشروع والتشغيل.
- `VERSION`: رقم الإصدار الموحد.

## حالة الإصدار 0.10.0

## تنبيه قبل الإطلاق
هذه حزمة تطوير جاهزة للرفع والمراجعة، وليست إثباتًا أن الخدمة تعمل في الإنتاج. يلزم ضبط أسرار البيئة على الاستضافة، وتجهيز PostgreSQL، وتشغيل الترحيلات بعد النسخ الاحتياطي، وبناء تطبيقات Flutter واختبار تسجيل الدخول والصلاحيات والتكامل قبل فتح الخدمة للعملاء. لا ترفع ملفات `.env` أو كلمات المرور أو مفاتيح Firebase إلى GitHub.

## تجهيز PostgreSQL محليًا — الإصدار 0.6.3
- يوجد `docker-compose.yml` لتشغيل PostgreSQL 16 محليًا. انسخ `.env.docker.example` إلى `.env` بجوار الملف، وغيّر كلمة المرور قبل التشغيل.
- شغّل `docker compose up -d postgres` من جذر المشروع.
- اضبط `DATABASE_URL` في `backend/.env`، ثم من مجلد `backend` شغّل `npm install` وبعده `npm run migrate:database` لتطبيق الترحيلات بترتيبها مع حفظ بصماتها ومنع التعديل الصامت على ترحيل مطبق.
- شغّل `npm run verify:database` ثم `npm run build`.
- راجع `STATUS_0.6.3_AR.md`. إعداد Docker والـ migrations مضافان في الملفات، لكن لم يتم تشغيلهما في بيئة الإنشاء الحالية.


## الإصدار 0.6.4 — إعدادات التسعير المرنة (تطوير)
- أضيف ترحيل `database/migrations/005_flexible_pricing.sql` بعد ترحيل المسارات.
- لوحة الإدارة تحفظ لكل تعرفة: رسوم العميل، ومستحق الكابتن الأساسي وبحسب المسافة/الوقت، ونسبة عمولة المنصة، وإعداد عرض افتتاح ثابت أو نسبي.

- لمراجعة ترتيب الترحيلات دون اتصال قاعدة البيانات: `cd backend && npm run migrate:database -- --plan`.
- لتطبيقها فعليًا: `cd backend && npm run migrate:database` بعد ضبط `DATABASE_URL`.
- راجع `STATUS_0.6.4_AR.md` وحدود الاختبار.
